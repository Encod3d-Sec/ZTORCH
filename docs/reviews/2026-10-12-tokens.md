# Token and context waste audit (2026-10-12)

Read-only audit of the ZTORCH harness (branch `hermes-integration`). All byte
figures below are measured this session, not estimated. `~tok = chars/4`.
Measured baseline: a fresh session carries ~50KB (~12.6K tok) of vault-side
fixed load before any work: AGENTS.md 24,834 + skill descriptions 14,333 +
ponytail plugin 5,252 + engagement-init 3,353 + hot.md 2,678 + memory snapshot
158. Per-tool-call cost is near zero on clean calls (the stamp discipline works);
the waste lives in repeat emissions and mis-firing advisories.

## Ranked issues

### 1. Mentor advisory fires on normal sequential work (top per-call offender)

- Evidence: `skills/hooks/tool-telemetry.py:215-263`. Keys are ANY binary name
  or tool name, threshold `_MENTOR_SAME_TOOL = 5`, reset-on-fire. This audit
  session (~40 tool calls) received 9 `LANE PATTERN (mentor)` injections (Read
  x3, grep x3, head, python3, find); each is ~230 chars + hook wrapper
  (~110 tok). The live engagement's `.metrics.json` shows counters at grep=4,
  git=3, echo=3, python3=2 in one bucket; 1,862 tool calls recorded in its
  `.events.jsonl`.
- Why it wastes: reading 5 files or running 5 greps in a row IS the analysis
  workflow, not a grind loop; the pentagi pattern was built for repeated
  identical exploit calls. Fires dozens of times per engagement
  (~50-100 x ~110 tok = 5-10K tok of identical text), and the noise trains the
  model to skim hook context.
- Fix: in `_mentor_check`, restrict keys to probe/exploit-shaped bins (reuse
  recon-capture's `PROBE_TOOLS` set) and drop pure read-tier names
  (Read/Grep/head/cat/sed/sort/uniq/ls); optionally add the 15-min
  `.ctx-low-stamp`-style dedupe every other advisory has.
- Effort: S. Saving: ~5-10K tok/engagement.

### 2. `offensive.py next` re-prints static boilerplate on every serve

- Evidence: measured full serve output = 1,426 bytes (live copy, row 4a:2).
  Static share: DEEP line 240B (`offensive.py:1196-1198`, deep is the default
  mode, prints every serve), APPROACH/AVOID/REFS 691B
  (`offensive.py:1248-1254`, fixed text per skill from playbook), PARALLEL
  240B (`offensive.py:1219-1223`, every serve in brain posture), G2
  parenthetical ~230B (`offensive.py:1275-1278`, every gated serve). 65% of
  every serve is text the model has already seen.
- Why it wastes: the driver runs dozens of times per engagement; only
  PASS/ROW/RE-SERVE/tool lines change between serves. ~1.1KB repeat x ~50
  serves = ~55KB (~14K tok) per engagement, pushing compaction earlier.
- Fix: persist in `.offensive.json` a `shown` map (`deep`, `parallel`, and
  per-skill `methods`); print each static block once per engagement (first
  serve per skill), trim the G2 parenthetical to one line.
- Effort: S/M. Saving: ~10-14K tok/engagement.

### 3. AGENTS.md at 24,834 chars (~6.2K tok) injected every session, mechanics duplicated in docs

- Evidence: `wc -c AGENTS.md` = 24,834; `docs/auto-triggers.md` = 23,380 more.
  The six-hook summary, Hunt Auto-Triggers, and Behavior-hooks sections restate
  docs/auto-triggers.md and triggers.json (`token-audit.py` flags the same
  number). The output-rules and delegate-mandate text also live in
  delegate/SKILL.md verbatim.
- Why it wastes: biggest single fixed cost; re-sent every session and
  re-summarized into every compaction summary, where it keeps costing.
- Fix: cut AGENTS.md to quick-reference tables + one-line pointers (target
  ~10-12K chars); mechanics stay in docs/ (loaded on demand). Keep the
  hard rules (client-data boundary, Obsidian-safe, log grammar) inline.
- Effort: M. Saving: ~3-4K tok/session.

### 4. Skill descriptions: 14,333 chars (~3.6K tok) in the always-on picker

- Evidence: summed frontmatter `description:` across 59 skills (several >400
  chars with multi-sentence trigger lists).
- Why it wastes: the picker list is harness-injected every session regardless
  of relevance; detail belongs in the SKILL.md body that loads on fire.
- Fix: cap descriptions at one sentence + trigger keywords (~200 chars each).
  Mechanical edit across 59 files.
- Effort: M. Saving: ~2K tok/session.

### 5. close-out.py "In flight at Stop" re-prints all open lanes every Stop

- Evidence: `skills/hooks/close-out.py:425-432` + `inflight_signals()`
  (`:23-120`): no dedupe marker. Live engagement has 3 STALE lane lines
  (~130B each) so every turn end injects ~450B of identical lane names.
- Why it wastes: lanes stay open for hours; hundreds of Stops each re-print
  the same unchanging lines the operator already decided about.
- Fix: hash the lane-line set into `.inflight-stamp`; print only when the set
  changed, else a one-line count ("3 lanes open, 3 STALE - status.py").
- Effort: S. Saving: ~0.5-2K tok/engagement.

### 6. Ponytail plugin injects 5,252 chars into EVERY SubagentStart

- Evidence: measured `getPonytailInstructions('full')` = 5,252 chars
  (~1.3K tok) via `plugins/cache/ponytail/.../hooks/ponytail-subagent.js`;
  unset `PONYTAIL_SUBAGENT_MATCHER` means every subagent pays it.
- Why it wastes: brain posture spawns 2-3 lanes plus forks continuously;
  10-30 subagents/engagement x 1.3K tok. Prompt caching softens API cost but
  the context window still fills.
- Fix (operator-level, no code): set `PONYTAIL_SUBAGENT_MATCHER` to the
  execution lane types, or `/ponytail lite` for subagent work; the plugin's
  own matcher env is the intended scope knob.
- Effort: S. Saving: ~13-40K tok of context per brain engagement.

### 7. engagement-init "Output caps" line duplicates AGENTS.md

- Evidence: `skills/hooks/engagement-init.py:479-482`, a 200-char static line
  appended to every SessionStart injection (present in the measured 3,353B
  output); the same rule is AGENTS.md "Brevity during engagements" verbatim.
- Fix: delete the append; AGENTS.md owns the rule.
- Effort: S. Saving: ~50 tok/session.

### 8. lane-guard advisory tier has no cooldown

- Evidence: `skills/hooks/lane-guard.py:206-213` `_emit`s an advisory on EVERY
  DANGEROUS-tier match; zg/tmux/burp-nudge all carry `INTERVAL = 900` stamps.
  With `skills/hooks/.enforce-off` present (this vault, Oct 6) hardline
  patterns ALSO become per-call advisories (`:193-197`).
- Why it wastes: `git reset --hard` / `curl|sh` shaped loops re-explain the
  ZT_ROE_OK pre-approval path on every call.
- Fix: add the 900s stamp pattern for the advisory tier (keep the hardline
  deny un-deduped while enforcing).
- Effort: S. Saving: situational 0.5-2K tok (destructive-ops-heavy sessions).

### 9. Memory nudge repeats its own command string

- Evidence: `skills/hooks/close-out.py:234-243`: the literal
  `python3 scripts/memory.py add --store operator|environment "fact"` string
  appears twice in one 440-char message (once mid-sentence, once at the end).
- Fix: keep one occurrence. Effort: S. Saving: ~100 tok per fire (every 10
  unanswered turns).

### 10. status.py full render overlaps SessionStart + `next` output

- Evidence: measured `scripts/status.py` output = 2,223B: board counts,
  deadends, lane lines, and 5 `Next moves` lines; engagement-init already
  injects 3 of those same `next_move.suggest()` lines at every session start
  and `offensive.py next` serves the move per turn.
- Why it wastes: habit-running status each turn re-derives ~2.2KB of mostly
  known state.
- Fix: add a `--diff` mode (state-stamped, prints only deltas since last
  run); steer mid-engagement use to it, keep the full render for close-out.
- Effort: M. Saving: ~1-2K tok/engagement.

## Already efficient (do not touch)

1. **SessionStart hot-cache discipline** (`session-start.sh`): hot.md rotates
   to `hot-archive.md` keeping 3 entries under a dual 200-line / 25KB cap
   (currently 2,678B); the memory snapshot is 158B with hard store budgets
   (1375/2200 chars, enforced by `scripts/memory.py`). Small, bounded, cached.
2. **Stamp discipline across the per-call hook fleet**: zg/tmux/burp-nudge
   (900s), drift-guard (15-min per-kind), recon-capture (GATE1 / board /
   serial nudges once-per-engagement; fingerprint routing once-per-tech via
   `.fp-fired`; wiki excerpt capped at 28 lines), capture-poc stall verdict
   (30-min). On a clean call all seven PreToolUse and three PostToolUse hooks
   print nothing.
3. **Disk-side telemetry + output econ**: `.events.jsonl` (291KB) and
   `.metrics.json` never enter context; `output_econ.py` stubs >30KB VM output
   to `ingest/` with a 2KB preview and tightens to 10KB when context is low;
   spend / context-low advisories are 15-min deduped. The big floods are
   already caught at the boundary that matters.

## Method

Ran the hooks the way the harness does (piped JSON stdin), measured a real
`offensive.py next` serve against a `/tmp` copy of the live engagement
(the active bugbounty engagement, 1,862 recorded tool calls), summed skill
frontmatter descriptions, and ran `scripts/token-audit.py`. No repo state was
modified; `/tmp/zt-audit` holds the throwaway copy.

# Agent-to-agent communication review (2026-10-12)

Scope: the lane contract as written (skills/workflow/brain/SKILL.md, skills/workflow/exec/delegate/SKILL.md, scripts/lane_validate.py, scripts/lane_envelope.py, scripts/status.py, scripts/spill-run.sh) vs as practiced on the one real brain engagement (2026-10-06 full run + 2026-10-12 dispatch test; its `targets/<eng>/log.md`, all line numbers below refer to that log: 40 `- lane` lines, 35 capture dirs, 30 `in flight` opens; validator + close-out sweep + postmortem parse re-run 2026-10-12).

## Envelope (top-3)

1. close-out.py re-implements capture-dir resolution without `_cap_dir`'s vault-prefix strip: its Stop-time over-claim sweep flags 27/27 honest lanes on this engagement and then poisons the `.lane-verify-nudged` dedup counter. Fix is one import. Effort S.
2. Lane-line format drift is invisible at dispatch time: the 3 fuzz lanes (~470 requests, log.md:92-97) carry no SUCCESS/tmux cells, match no regex, get no aging, no drift-guard exemption, no verdict check; only eng-postmortem sees them, post-hoc. Effort M.
3. The envelope.json contract is fully dormant: 0 files in 35 capture dirs, `--envelope` mode run by nothing (no hook, no skill step), so PENDING-WRITE has no on-disk twin and return-message-only state can evaporate. Effort M.

## Defects (ranked)

### 1. close-out sweep false-flags every lane (DRY violation)

- Evidence: skills/hooks/close-out.py:48-52 joins the capture cell its own way; scripts/lane_validate.py:188-199 (`_cap_dir`) exists precisely because cells are vault-spelled (`capture targets/<eng>/poc/...`). Replicated today: close-out resolution flags 27/27 lanes NOT VERIFIED; `_cap_dir` resolution flags 2/27 (both false, see #3). `.lane-verify-nudged` absent, so the nudge has never fired here yet; when it does, it writes `27` and a genuine 28th over-claim never re-nudges (dedup only fires on `len(_bad) > last`).
- Consequence: the ONE automatic verifier (delegate prose is the only other check) cries wolf on every lane, then goes permanently deaf.
- Fix: close-out imports and calls `lane_validate._cap_dir`. Effort S.

### 2. Dispatch-time format drift: lanes outside every mechanical layer

- Evidence: log.md:92-94 (laneAA-fz1, laneAB-fz2, laneAC-fz3 opened `in flight @14:52` with NO `SUCCESS =` and no tmux cell), closed via separate `done @15:02` lines (95-97) in a second grammar; three more grammar variants at lines 62, 110-112. `_LANE_RE` (lane_validate.py:32) matches none of them, so lane_validate, status.py aging, drift-guard's `fresh_lane_open`, and the close-out closed-lane sweep all skip the entire fuzz wave. Only eng-postmortem.parse reports "lane line missing envelope cells" (verified: 10 hits), and only at learn time.
- Consequence: 3 of the engagement's heaviest lanes have zero mechanical provenance; mid-wave, the brain's own calls got no lane-contact drift exemption from them; a compaction in that window would have lost their state entirely.
- Fix: validate the lane line AT WRITE TIME (the brain is the only writer): a `lane_validate --open <log>` pass that must print the new line back before dispatch proceeds, or fold into the drift-guard PreToolUse advisory. Effort M.

### 3. SUCCESS criteria prose leaks into checkable tokens: false NOT VERIFIED

- Evidence: laneA-4a1 (log.md:34) criterion `poc/laneA-4a1/{probe-results.tsv>=150 rows, js-audit.md 10 hosts, candidates.md}`: `_checkable_lits` (lane_validate.py:165-185) treats `{probe-results.tsv>=150` as a substring literal; absent -> NOT VERIFIED, yet all three files exist on disk with the claimed content. laneL-rtl7 (log.md:55): prose token `uuid?key=other)` matches the `\w=` structural rule -> NOT VERIFIED while assets-followup.md (2402B) + f1-f3 raws sit in the dir. The module's own comment documents a third instance (lane-apipl-sqli, 2026-09-29). Rate today: 2/28 = 7% false negatives.
- Consequence: an honest lane reads "over-claim"; NOT VERIFIED trains as noise, and inside the close-out nudge (#1) a real over-claim hides among false ones.
- Fix: a criterion grammar the parser owns: checkable tokens must be backticked or named files; everything after a `|` in the SUCCESS cell is prose the validator ignores (the `>=` guard at lane_validate.py:181 generalizes to "only backticked strings are substrings"). Effort S.

### 4. Closure written as a separate line leaves lanes open forever

- Evidence: log.md:106-108 (laneQ-rtl5, laneR-wiki, laneS-graph, `in flight @09:12`) never closed; the STOPPED verdicts live at 110-112 in a different grammar. Re-ran `lane_lines` today: all three surface as `(372min) STALE - resume via its handle`. Delegate SKILL.md documents the exact trap ("a verdict written only as a separate line leaves the lane line reading `in flight` forever") but nothing detects or repairs it; SessionStart (engagement-init.py:371-372) will re-inject them every session.
- Consequence: permanent phantom lanes; the stale advisory competes with real ones; "resume via its handle" points at #5's reused handle.
- Fix: a pairing lint (SessionStart or find-lint): any `- lane <name>` open line with a later `- lane <name> ->` line anywhere gets flagged for append-closure. Effort S.

### 5. Handle/nonce bookkeeping is manual, unvalidated, and already wrong once

- Evidence: `handle aef80e006c8a24338` appears twice, laneY-drift2 (log.md:85, closed VERIFIED 10-06) and laneQ-rtl5 (log.md:106, the stale-open board lane, 10-12). The steer-nonce (`handle <id>#<nonce>`, brain SKILL.md:136-139) appears zero times in 40 lane lines; nothing in lane_validate, hooks, or the skills ever checks nonce presence, format, or handle uniqueness.
- Consequence: the resume path for the one lane status.py actively tells you to resume resolves to a different (finished) lane's agent; the anti-steer-spoof authentication the brain spec promises was never exercised, so a target-content "steer" today would be indistinguishable from a real one.
- Fix: emit handle+nonce from a tiny helper at dispatch and have the lane-line lint (#4) reject duplicate handles; steer auth stays prose until then. Effort S.

### 6. envelope.json: contract shipped, enforcement zero

- Evidence: `find targets/<eng> -name envelope.json` -> nothing, across all 35 capture dirs. lane_envelope.py `init` is invoked by no script, hook, or skill step; `lane_validate.py --envelope` likewise (grep across scripts/, skills/, setup/: only the two skill docs and port-specs mention it). brain SKILL.md's ENVELOPE-MISSING re-prompt flow has never had a subject.
- Consequence: the machine-readable return twin (scope/result/key_files/issues/pending_write) never exists; every integration keyed on it (re-prompt retry, NOT VERIFIED filing, cross-check of `success_observable_raw`) is dead code in practice.
- Fix: wire `lane_envelope init` into the dispatch moment (the brain creates the capture dir anyway; one line beside the lane-line write) and one line in the returned-lane processing order: run `--envelope` beside `lane_validate`. Effort M.

### 7. PENDING-WRITE exists only in the volatile return message

- Evidence: delegate SKILL.md ("a PENDING-WRITE never silently evaporates") and the schema field (`pending_write`, lane_envelope.py:32) vs zero occurrences in the field and no on-disk representation anywhere; grep of the log for `PENDING-WRITE` -> 0. The 10-12 dispatch test is the live demonstration of return-message volatility: three lanes stopped, and their partial results ("scope window check done", "commands clean") survive only as one-line log summaries with EMPTY capture dirs (poc/laneQ-rtl5, laneR-wiki, laneS-graph: 0 files).
- Consequence: a compaction or session death between return and apply silently destroys exactly the writes the mechanism exists to protect; nothing sweeps for unapplied pending writes at close-out.
- Fix: the schema already has the field: once #6 wires envelope.json, add a close-out sweep for non-empty `pending_write` arrays never applied (state.md lacks the key). Effort S once #6 lands.

### 8. Dateless `@<HH:MM>` cells: stale-evidence advisory false-positives on any later-day run

- Evidence: every one of the 28 closed lanes printed `STALE-EVIDENCE: ... predates lane open` in today's validator run, because `stale_evidence` (lane_validate.py:300-326) rebuilds the open timestamp with TODAY's date; the engagement ran 10-06, today is 10-12. The `@HH:MM>` cell carries no date and the parser does not use the enclosing session header.
- Consequence: a 100% false-positive rate on post-engagement re-runs (close-out, learn, this review) for an advisory meant to catch claims resting on pre-existing artifacts; pure noise that trains skipping advisories, and it would mask the one real case it was built for.
- Fix: derive the date from the nearest preceding `## YYYY-MM-DD` session header in lane_lines/stale_evidence (the log always has one), or store `@<YYYY-MM-DD HH:MM>`. Effort S.

### 9. Usage cells never populated: lane cost accounting is zero

- Evidence: `usages_from_text` (lane_validate.py:250-262) and eng_postmortem's `tokens/wall_s` parse `| usage <n>t/<n>s`; grep of the log -> 0 occurrences. The hermes port's per-lane window/budget cells (wave 5c) share the fate.
- Consequence: tier routing (flash vs mid, "the cost metric is turn count") has no feedback signal; postmortems render 0 tokens 0 seconds for every lane; the token+context posture port is unwired on the lane side.
- Fix: the Agent tool's return carries usage; make appending the usage cell part of the same close-out step as the verdict append (and let the lane-line lint check it). Effort S.

### 10. Briefs not staged in capture dirs despite the documented ceiling and a live precedent

- Evidence: brain SKILL.md known-ceilings says to stage a copy of the shared prefix + directive in the lane's capture dir if a compaction could land in the spawn window; `find poc -iname '*brief*' -o -iname '*prompt*'` -> nothing across 35 dirs. Precedent: log.md:38, laneC-4a2's first spawn died on a corrupt prompt and had to be re-authored from brain memory (the re-dispatch worked only because the brain still held the brief).
- Consequence: the only artifact that defines what a lane was told lives in a prompt that compaction can eat; a post-compaction brain cannot audit whether a lane's claim answers the brief it actually received.
- Fix: `cp <brief> <capture-dir>/brief.md` at dispatch (or `lane_envelope init --brief <path>` once #6 wires it). Effort S.

## What works well

1. One regex, five consumers, one clock. `_LANE_RE` and the 45-min aging live only in lane_validate.py and are imported by status.py, engagement-init (SessionStart re-inject), drift-guard (`fresh_lane_open`, the same clock by construction), close-out, and eng-postmortem. No parser drift between the surfaces; the drift-guard exemption expiring on the same clock status.py ages by is exactly right.
2. The capture dir as the lane-to-brain (and lane-to-lane) blackboard. Every spot-checked closed lane's dir contains what its lane line claims (laneA-4a1's tsv/js-audit/candidates, laneL-rtl7's md + f1-f3, the fuzz csv/log sets, laneAD-fz4's 30 pairs); the brain's VERIFIED verdicts matched disk reality in all 28 cases (both NOT VERIFIEDs today were validator false positives, not bad lanes). Cross-lane handoff worked with no direct channel: laneQ-t12 consumed laneP's extracted src by brain-named path (log.md:70), which is the right shape, disjointness preserved, provenance named in the line. No lane-to-lane channel is needed; the brain-mediated path naming IS the channel.
3. Verdict-on-the-line discipline held under load. 28/30 lanes closed with the verdict appended to the lane line itself, verdict above the claim, each VERIFIED citing concrete disk state (file + line counts); negatives carried classable reasons (CLOSED-NEGATIVE, dead-with-evidence, explicit contract-change flags on a re-verify lane). Six session boundaries (six `session ... start` headers) and the work resumed mid-wave with no visible re-derivation, which is the post-compact re-inject design doing its job. The pre-flight `Ruling:` rows before every multi-lane wave (collision table, RoE checks) are real and present, 11 of them.

## Not defects (checked)

- Lane-to-lane channel: not needed, see above.
- spill-run.sh: output-side tool, correctly fail-open, referenced by tool-telemetry's advisory; no lane-contract interaction to break.
- `tmux win -` on every lane: the VM seat was dead this engagement (log.md:39), so the cell is honestly a placeholder; the cell staying mandatory (parses for aging) is the right call.

# ZTorch on Hermes

## What this is

This vault (ZTorch) is an autonomous offensive-security harness for AUTHORIZED work only:
signed pentests, in-scope bug bounty, own lab/CTF. Hermes sessions in this tree follow the
ZTorch discipline below. Full canon: `AGENTS.md` (ZCode seat), `docs/`, `skills/`.

## Hard rules (never violated)

1. **Authorized targets only.** Before any packet leaves: `targets/<eng>/scope.md` exists and
   the target is in it. Out-of-scope hosts/IPs are the ONE hook-enforced deny in ZTorch and
   the ONE hard refusal here. RoE-forbidden tooling (bruteforce, DoS, passive-only) is an
   OPERATOR decision: ask, never assume.
2. **Client-data boundary.** Hosts, IPs, creds, domains, findings, engagement narrative live
   ONLY under `targets/<eng>/` (git-ignored). Never into `wiki/`, `docs/`, `skills/`,
   `session/`, commit messages, Hermes memory entries, or anything that leaves this machine. Never debug-share or export a Hermes session from this tree.
   Before sharing/pushing any file from this tree: `bash scripts/check-leaks.sh` must pass.
3. **No claim without fresh capture.** A CONFIRMED/EXPLOITED claim requires the proving
   command's raw output read this session, with an on-disk capture path under `poc/`.
   Blind vulns (SSRF/SSTI/blind SQLi/deser) require an out-of-band callback. Inference is
   never evidence. A negative (no callback, empty response) is a hypothesis until re-verified.
4. **State-first, anti-loop.** Before any recon/exploit: read `targets/<eng>/state.md`,
   `loot.md`, `Killchain.md`, `Deadends.md`. Never re-run a documented dead-end without new
   input. A vector is exhausted after bounded effort: one Deadends line (`ladder:` included),
   then switch. Do not grind.
5. **Obsidian-safe markdown.** Any angle-bracketed value in a vault page sits in inline
   backticks (`` `<token>` ``); bare `<token>` renders as an HTML tag and swallows the page.
   No em-dashes in prose, no emoji, balanced code fences.

## Session contract (boot sequence)

1. `read_file targets/active.md` -> engagement name (empty = no active engagement; framework work only).
1b. `read_file session/hot.md` (continuity cache written at session end).
2. If engagement active: read `targets/<eng>/state.md`, `loot.md`, `Killchain.md`, `Deadends.md`, `scope.md`.
3. Load `engage` skill (router) for engagement work; follow `offensive` (driver `scripts/offensive.py`) output literally when running a campaign.
4. Wiki-first: query the wiki BEFORE any attack decision (tool map below).

## Tool map

- **Wiki search (first rung):** MCP `wiki` -> `wiki_query` (search; `lex:"<terms>"` for
  keyword/exact tokens like CVE IDs, plain text for semantic), `wiki_get` (read a page),
  `wiki_status` (index health). Queries in English. Never browse `wiki/index.md` to find pages.
  Seat quirks: `qmd embed` needs `--no-gpu` and catches up over several passes
  (`LLM session expired` lines mid-pass are normal; re-run until Vectors stops climbing);
  the semantic query-expansion LLM fails on this seat (VRAM exhausted) - `lex:` typed
  queries are the reliable rung.
- **Fallback ladder (wiki down):** rung 2: `QMD_VAULT='C:/Users/Lenovo/Documents/ObisidianVaults/ZTorch/ZTorch' bash scripts/wiki-query.sh "<query>"` (from vault root);
  rung 3: `search_files(pattern="<terms>", path="<vault>/wiki", target="content")` + `read_file`.
- **Cross-file locate:** `search_files` (ripgrep) to locate, `read_file` to read. Grep inside one file only.
- **VM bridge (2026-10-11):** heavy tooling runs on the Kali VM over direct ssh:
  `ssh kali-vm '<cmd>'` (alias in Windows `~/.ssh/config`, key auth as `tz`, details:
  `kali-seat` skill, `docs/virtual-machine.md`). The old `scripts/vm-ssh.sh` path is
  WSL-seat only - do not use it from Windows.
- **Multi-agent:** `delegate_task` for fully-specified execution lanes (model pin:
  glm-5.3-flash); main session keeps strategy/driver/triage on glm-5.3. **Placement law
  (W3):** judgment-shaped work NEVER enters delegate_task while the global flash pin is
  set - verifier calls, triage, discovery-negative re-checks, and anything feeding
  Deadends.md run in the main session only; a child's negative is a hypothesis until
  re-verified on main. Verbatim mandates ride in every delegation prompt: read-first
  (`cat` each file in full, grep only to locate), Obsidian-safe backticks,
  no-claim-without-fresh-capture, no-give-up (report raw output, never invent a result).
